# harness_image — standalone AgentCore bundle builder and deployer

This package builds and deploys the Amazon Bedrock AgentCore runtime bundles for the
three coding harnesses (claude, codex, kiro). It is the **image component** of
multi-coding-harness-compare and runs without the UI application (`arena/`) installed.

## What it does

- Resolves harness versions from one of three sources: `pinned` (default), `installed`
  (the CLI currently on PATH), or `latest` (fetches from npm / PyPI / CDN).
- Builds per-harness `deployment_package.zip` bundles containing the harness CLI,
  Python wheels, and the in-VM supervisor (`arena/agentcore_agent.py`).
- Creates or refreshes the IAM execution role and its inline policy.
- Creates or updates the three AgentCore runtime resources and waits for `READY` status.
- Writes runtime ARNs to `DATA_DIR/agentcore-runtimes.json` (shared with the UI app).

## Quick start

No `arena/` install needed; only `uv` and Python 3.12 must be present.

```bash
bash deploy/agentcore-deploy.sh plan                 # show what would be deployed
bash deploy/agentcore-deploy.sh deploy               # deploy all three harnesses
bash deploy/agentcore-deploy.sh deploy --approve TOKEN  # non-pinned versions need approval
bash deploy/agentcore-deploy.sh status               # list deployed runtimes
bash deploy/agentcore-deploy.sh policy --kind execution   # print execution role policy
```

Or use `python -m harness_image` directly from the virtualenv:

```bash
python -m harness_image plan
python -m harness_image deploy --harness claude --no-rebuild
python -m harness_image policy --kind deployer
```

## Configuration

All inputs come from `deploy.properties` (same file as the UI app). Relevant keys:

| Key | Default | Purpose |
|---|---|---|
| `AWS_PROFILE` | ambient chain | AWS credentials for IAM and AgentCore API calls |
| `AWS_REGION` | `us-east-1` | Region for AgentCore runtimes |
| `AGENTCORE_TRANSFER_S3_URI` | required | `s3://bucket/prefix/` for deployment bundles |
| `AGENTCORE_EXECUTION_ROLE_NAME` | `CodeCouncilBedrockAgentCoreRuntimeRole` | IAM role name |
| `AGENTCORE_TRANSFER_KMS_KEY_ARN` | unset | KMS key ARN for SSE-KMS on the transfer bucket |
| `USER_NAMESPACE` | unset | Suffix for per-user isolation (`AGENTCORE_ISOLATION=per-user`) |
| `CLAUDE_HARNESS_SOURCE` | `pinned` | `pinned` / `installed` / `latest` |
| `CLAUDE_HARNESS_VERSION` | — | Explicit version; overrides the source strategy |
| `CODEX_HARNESS_SOURCE` | `pinned` | same |
| `CODEX_HARNESS_VERSION` | — | |
| `KIRO_HARNESS_SOURCE` | `pinned` | same |
| `KIRO_HARNESS_VERSION` | — | |
| `HARNESS_TRUSTED_SOURCES` | registry.npmjs.org,pypi.org,files.pythonhosted.org,desktop-release.q.us-east-1.amazonaws.com | Comma-separated allowed download hostnames |
| `KIRO_DOWNLOAD_URL` | CDN template | Override Kiro CDN URL |
| `HARNESS_IMAGE_WORKSTATION_CONFIG` | `false` | Bake workstation config snapshot into bundle |

## Version sources

| Source | How version is resolved | Approval token required |
|---|---|---|
| `pinned` | Constants in `harness_image/versions.py` | No |
| `installed` | `claude --version` / `codex --version` / `kiro-cli --version` | Yes (plan first) |
| `latest` | npm registry / PyPI / CDN | Yes (plan first) |

When the source is `installed` or `latest`, a lock file at
`DATA_DIR/harness-versions.lock.json` must contain the approved version, URI, and digest
for each harness. Run `plan` to see the token; pass `--approve TOKEN` to `deploy` once the
output has been reviewed.

## IAM policies

The three policy kinds can be printed as JSON for manual review or use in CloudFormation:

```bash
python -m harness_image policy --kind execution    # runtime execution role
python -m harness_image policy --kind deployer     # workstation profile for --deploy
python -m harness_image policy --kind workstation  # workstation profile for API/worker
```

Stored reference documents are in `docs/iam/`; they are regenerated by
`tests/test_docs_policies.py` and any drift fails that test.

## Interface with the UI application

| Artifact | Produced by | Consumed by |
|---|---|---|
| `DATA_DIR/agentcore-runtimes.json` | `harness_image` deploy | `arena/` probe and session |
| `DATA_DIR/harness-versions.lock.json` | `harness_image` plan/deploy | `harness_image` deploy, preflight |
| `deploy.properties` | operator / bootstrap.sh | both components |

`harness_image` does not import `arena`; it is importable and deployable with `arena` absent.
The `arena` package imports `harness_image` through a thin re-export shim
(`arena/agentcore_provision.py`) so existing callers keep working.
